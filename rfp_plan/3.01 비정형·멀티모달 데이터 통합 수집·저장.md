# 3.01 비정형·멀티모달 데이터 통합 수집·저장 - 구현 방법론

## 3.01.1 개요

선급 업무에서 발생하는 정형·비정형·멀티모달 데이터 전체를 단일 플랫폼에서 수집·저장·관리하기 위한 구현 방법론을 기술한다.

---

## 3.01.2 데이터 유형별 수집 전략

### A. 정형 데이터
| 데이터 유형 | 수집 방식 | 저장 위치 |
|------------|----------|----------|
| 해석 결과 (수치) | API 연동 / 배치 Import | RDBMS (PostgreSQL) |
| DB 레코드 | ETL 파이프라인 | RDBMS |
| CSV/Excel 테이블 | 파일 업로드 → 파싱 → DB 적재 | RDBMS + 원본 Object Storage |

### B. 비정형 데이터
| 데이터 유형 | 수집 방식 | 저장 위치 |
|------------|----------|----------|
| 보고서 (PDF/DOCX) | 수동 업로드 / 폴더 감시(Watcher) | Object Storage (MinIO/S3) |
| 이미지 (JPG/PNG/TIFF) | 수동 업로드 / 스캐너 연동 | Object Storage |
| 로그 파일 | 디렉토리 Watcher / Syslog 수집 | Object Storage + 시계열DB |
| 스캔 데이터 | HullScan 출력 폴더 Watcher | Object Storage |

### C. 멀티모달 데이터
| 데이터 유형 | 수집 방식 | 저장 위치 |
|------------|----------|----------|
| 3D 모델 (STEP/IGES/STL) | 수동 업로드 / Frame3D 출력 연동 | Object Storage |
| 도면 (DWG/DXF/PDF) | 수동 업로드 / 폴더 감시 | Object Storage |
| 영상 (MP4 등) | 수동 업로드 | Object Storage (대용량 계층) |
| 센서 데이터 (시계열) | MQTT/REST API 실시간 수집 | 시계열DB (TimescaleDB/InfluxDB) |

## 3.01.4 저장소 설계

### 계층형 저장소 구조 (Hot / Cool / Archive)

| 계층 | 대상 | 접근 빈도 | 저장 기술 |
|------|------|----------|----------|
| **Hot** | 최근 6개월 데이터, 활성 프로젝트 | 높음 | SSD 기반 Object Storage |
| **Cool** | 6개월~2년, 참조용 | 중간 | HDD 기반 Object Storage |
| **Archive** | 2년 이상, 법적 보존 | 낮음 | 저비용 Cold Storage / Tape |

### 저장소 구성 요소

```
┌──────────────────────────────────────────┐
│              Object Storage (MinIO/S3)    │
│  /raw/          ← 원본 파일 (불변)        │
│  /processed/    ← 가공 결과물             │
│  /thumbnails/   ← 프리뷰/썸네일           │
│  /temp/         ← 임시 작업 공간          │
├──────────────────────────────────────────┤
│              RDBMS (PostgreSQL)           │
│  metadata       ← 파일 메타정보           │
│  projects       ← 프로젝트/조직 구조      │
│  audit_logs     ← 감사 로그              │
├──────────────────────────────────────────┤
│              Elasticsearch               │
│  file_index     ← 전문 검색 색인          │
│  meta_index     ← 메타데이터 검색 색인     │
└──────────────────────────────────────────┘
```

## 3.01.5 대용량 파일 업로드 처리

### Chunked Upload (분할 업로드)
1. 클라이언트에서 파일을 **청크(5~100MB 단위)**로 분할
2. 각 청크에 순번 + 해시값 부여 후 개별 전송
3. 서버에서 청크 수신 확인 → 실패 시 **해당 청크만 재전송**
4. 모든 청크 수신 완료 → 조립 → 무결성 검증(전체 해시)
5. 업로드 **중단 재개(Resume)** 지원: 마지막 성공 청크부터 이어서 전송

### 구현 기술
- **프로토콜**: TUS(Resumable Upload Protocol) 또는 Multipart Upload API
- **프론트엔드**: Uppy / FilePond 등 청크 업로드 지원 라이브러리
- **백엔드**: Node.js/Python 스트리밍 수신 → Object Storage Direct Write
- **진행률 표시**: WebSocket 기반 실시간 업로드 상태 전달

## 3.01.6 메타데이터 자동 추출

### 파일 유형별 추출 항목

| 파일 유형 | 추출 메타데이터 |
|----------|---------------|
| PDF/문서 | 제목, 저자, 페이지 수, 생성일, 텍스트 내용(OCR 포함) |
| 이미지 | 해상도, 색공간, EXIF(촬영일/GPS), 파일 크기 |
| 3D 모델 | 정점 수, 면 수, 바운딩 박스, 파일 포맷, 단위 |
| CAD 도면 | 레이어 정보, 축척, 좌표 범위 |
| 센서 로그 | 시작/종료 시각, 채널 수, 샘플링 주기, 데이터 포인트 수 |

### 추출 엔진 구성
- **범용 메타**: Apache Tika (PDF/DOCX/이미지/다수 포맷 지원)
- **3D 모델**: Open Asset Import Library (Assimp), OCCT
- **CAD**: ODA SDK, LibreDWG
- **센서 데이터**: 커스텀 파서 (포맷별 플러그인 구조)

## 3.01.7 검색·필터링 체계

### 검색 유형
1. **키워드 검색**: 파일명, 메타데이터 필드, 문서 내 텍스트 전문검색
2. **조건 검색**: 프로젝트 / 기간 / 파일 유형 / 태그 / 상태 조합 필터
3. **유사 검색**: 벡터 임베딩 기반 유사 데이터 검색 (향후 확장)

### 색인 전략
- **Elasticsearch** 기반 역색인 구조
- 파일 등록 시 비동기로 색인 갱신 (Event-Driven)
- 한국어/영어 형태소 분석기 적용 (nori / standard analyzer)
- 자동 완성(Auto-Complete) 및 오타 보정(Fuzzy Match) 지원

## 3.01.8 데이터 통합 관리 모델

### Unified Data Object (UDO) 스키마

모든 유형의 데이터를 동일한 인터페이스로 관리하기 위한 범용 데이터 객체:

```
UDO {
  id:           UUID
  name:         string          // 파일명/데이터명
  type:         enum            // structured | unstructured | multimodal
  mime_type:    string          // application/pdf, model/step, ...
  size:         number          // 바이트
  storage_path: string          // Object Storage 경로
  checksum:     string          // SHA-256 해시
  project_id:   UUID            // 소속 프로젝트
  owner_id:     UUID            // 등록자
  tags:         string[]        // 사용자 태그
  metadata:     JSONB           // 파일 유형별 추출 메타 (유연 확장)
  version:      number          // 버전 번호
  status:       enum            // active | archived | deleted
  created_at:   timestamp
  updated_at:   timestamp
}
```

이 스키마를 통해 데이터 유형에 무관하게 **등록·조회·검색·버전 관리·권한 제어**를 통일된 API로 수행한다.
