# 3.03 비정형 → 정형 데이터 추출 파이프라인 - 구현 방법론

## 3.03.1 개요

수집된 멀티모달·비정형 데이터에서 정형 데이터를 자동·반자동으로 추출·변환하는 파이프라인을 구현한다. 본 단계는 엔드투엔드 데이터 파이프라인에서 **수집(3.01) 이후, 분석(3.04) 이전**에 위치한다.

```
┌─────────┐    ┌──────────┐    ┌──────────┐    ┌──────────┐    ┌──────────┐
│ 멀티모달  │    │  정형     │    │  탐색적   │    │  모델    │    │  예측    │
│ 데이터    │ →  │  데이터   │ →  │  데이터   │ →  │  학습    │ →  │  추론    │
│ 수집     │    │  추출     │    │  분석     │    │  (ML)    │    │  실행    │
└─────────┘    └──────────┘    └──────────┘    └──────────┘    └──────────┘
  (3.01)        ▶ 본 문서      (3.04)          (3.05)          (3.05)
```

## 3.03.2 추출 유형별 구현 방법론

### A. 보고서 (PDF/문서) → 테이블·수치 추출

**처리 흐름**:
```
PDF/문서 입력
  │
  ├─ 텍스트 레이어 존재? ─→ Yes ─→ Apache Tika / PDFBox 텍스트 추출
  │                        No ─→ Tesseract OCR (한국어/영어)
  │
  ├─ 테이블 감지 (Camelot / Tabula)
  │   └─ 테이블 구조 인식 → 행/열 매핑 → DataFrame 변환
  │
  ├─ 수치 파싱 (정규식 + NLP)
  │   └─ 핵심 수치값 추출 (두께, 응력, 치수, 좌표 등)
  │   └─ 단위 자동 인식·통일 (mm, MPa, ...)
  │
  └─ 구조화 출력
      └─ CSV / DB 테이블 형태로 변환·저장
```

**변환 예시**:
```
PDF 보고서                        추출 결과
┌──────────────────┐             ┌──────────────────────┐
│ 측정 결과          │             │ location | thickness  │
│ Frame 10: 12.5mm  │  ──────→   │ Frame 10 | 12.5      │
│ Frame 11: 11.8mm  │             │ Frame 11 | 11.8      │
│ Frame 12: 13.1mm  │             │ Frame 12 | 13.1      │
└──────────────────┘             └──────────────────────┘
```

**핵심 기술**:
| 단계 | 기술 | 비고 |
|------|------|------|
| 텍스트 추출 | Apache Tika, PDFBox | 다양한 포맷 지원 |
| OCR | Tesseract 5.x + 한국어 학습 데이터 | 스캔 문서 대응 |
| 테이블 감지 | Camelot (격자형), Tabula (비격자) | 테이블 구조별 분리 |
| 수치 파싱 | 정규식 + spaCy NER | 도메인 특화 패턴 |
| 단위 처리 | Pint (Python 단위 라이브러리) | 자동 단위 변환 |

### B. 3D 모델·도면 → 치수·형상 파라미터 추출

**처리 흐름**:
```
3D 모델 (STEP/IGES/STL)
  │
  ├─ 모델 파싱 (OpenCASCADE / Assimp)
  │   └─ 기하학적 요소 분해 (면, 선, 점)
  │
  ├─ 전체 형상 분석
  │   └─ 바운딩 박스, 표면적, 체적, 무게중심
  │
  ├─ 구조 요소 식별·분류
  │   ├─ 판 (Plate): 위치, 두께, 면적
  │   ├─ 보강재 (Stiffener): 유형(T-bar/L-bar/FB), 치수, 간격
  │   ├─ 프레임 (Frame): 위치, 단면 치수
  │   └─ 기타 요소: 브래킷, 칸막이 등
  │
  └─ 파라미터 테이블화
      └─ 각 요소의 {ID, 유형, 위치, 치수, 재질} → 정형 테이블
```

**변환 예시**:
```
3D 모델 (STEP/STL)                추출 결과
┌──────────────────┐             ┌──────────────────────────────┐
│   [3D 선체 모델]   │             │ element  | type   | thickness │
│                   │  ──────→   │ Plate-01 | plate  | 12.0      │
│                   │             │ Stiff-01 | T-bar  | 8.5       │
│                   │             │ Frame-10 | frame  | 15.0      │
└──────────────────┘             └──────────────────────────────┘
```

**핵심 기술**:
| 단계 | 기술 | 비고 |
|------|------|------|
| 모델 파싱 | OpenCASCADE (OCCT) | STEP/IGES 정밀 파싱 |
| 메시 처리 | Assimp, trimesh | STL/OBJ 메시 분석 |
| 형상 분석 | OCCT BRepTools | 표면적/체적/치수 계산 |
| 요소 분류 | 규칙 기반 + ML 보조 | 도메인 특화 분류기 |
| CAD 도면 | ODA SDK, LibreDWG | DWG/DXF 파싱 |

### C. 이미지·스캔 데이터 → 결함 정량화

**처리 흐름**:
```
스캔 이미지 (JPG/PNG/TIFF)
  │
  ├─ 전처리 (OpenCV)
  │   └─ 노이즈 제거, 대비 보정, 정규화, 크기 표준화
  │
  ├─ 결함 감지 (딥러닝)
  │   ├─ Object Detection: YOLO v8 → 결함 바운딩 박스
  │   └─ Instance Segmentation: Mask R-CNN → 결함 영역 마스크
  │
  ├─ 결함 측정
  │   ├─ 바운딩 박스 → 실제 치수 매핑 (캘리브레이션)
  │   ├─ 면적 계산 (픽셀 → mm²)
  │   └─ 깊이 추정 (스테레오/구조광 데이터 있을 경우)
  │
  ├─ 결함 분류
  │   └─ 부식(corrosion), 균열(crack), 변형(dent), 도장박리(coating loss)
  │
  └─ 정량화 테이블 출력
      └─ {결함ID, 유형, 위치, 면적, 심각도등급} → 정형 데이터
```

**변환 예시**:
```
스캔 이미지                       추출 결과
┌──────────────────┐             ┌──────────────────────────────────────┐
│   [선체 스캔]      │             │ defect_id | type      | area_mm2    │
│   ■ ← 부식        │  ──────→   │ D-001     | corrosion | 245.3       │
│   / ← 균열        │             │ D-002     | crack     | 18.7        │
└──────────────────┘             │ D-003     | dent      | 120.5       │
                                 └──────────────────────────────────────┘
```

**핵심 기술**:
| 단계 | 기술 | 비고 |
|------|------|------|
| 전처리 | OpenCV | 이미지 정규화·보정 |
| 결함 감지 | YOLOv8 / Mask R-CNN | 사전 학습 + 선급 데이터 파인튜닝 |
| 캘리브레이션 | 스케일 참조 마커 | 픽셀-실제 치수 매핑 |
| 결함 분류 | CNN 분류기 (ResNet/EfficientNet) | 선급 결함 분류 체계 적용 |
| 심각도 판정 | 규칙 기반 + ML | IMO/IACS 기준 연동 |

### D. 로그·센서 데이터 → 시계열 정형 변환

**처리 흐름**:
```
로그/센서 원본 데이터
  │
  ├─ 로그 파싱
  │   └─ 정규식 기반 파서: 타임스탬프 + 이벤트 + 값 분리
  │   └─ 포맷별 플러그인: syslog, JSON 로그, CSV 센서, 바이너리
  │
  ├─ 타임스탬프 정규화
  │   └─ 다양한 시간 포맷 → ISO 8601 통일
  │   └─ 타임존 보정
  │
  ├─ 리샘플링 (균일 간격 변환)
  │   └─ 불균일 간격 → 지정 간격 (1초/1분/1시간)으로 정규화
  │   └─ 보간 방식: linear / forward fill / spline
  │
  ├─ 결측치 처리
  │   └─ 보간(interpolation) 또는 NaN 플래그 처리
  │   └─ 결측 구간이 임계값 초과 시 사용자 알림
  │
  ├─ 피처 엔지니어링 (자동)
  │   └─ 이동평균, 변화율, 최대/최소, 표준편차
  │   └─ 윈도우 크기: 사용자 설정 또는 자동 최적화
  │
  └─ 시계열 DB 적재
      └─ TimescaleDB / InfluxDB에 정형 시계열로 저장
      └─ 태그 기반 인덱싱 (센서ID, 위치, 채널)
```

**핵심 기술**:
| 단계 | 기술 | 비고 |
|------|------|------|
| 로그 파싱 | 커스텀 파서 (플러그인 구조) | 포맷별 확장 가능 |
| 시계열 처리 | Pandas / Polars | 리샘플링·보간·집계 |
| 피처 생성 | tsfresh / featuretools | 자동 피처 엔지니어링 |
| 시계열 DB | TimescaleDB 또는 InfluxDB | 고속 시계열 쿼리 |

## 3.03.3 추출 파이프라인 관리

### 추출 작업(Extraction Job) 모델

```
ExtractionJob {
  id:              UUID
  source_data_id:  UUID            // 원본 데이터 (UDO) 참조
  extractor_type:  string          // 'pdf_table' | '3d_geometry' | 'image_defect' | 'timeseries'
  config:          JSONB            // 추출 파라미터 (ROI, 임계값, 간격 등)
  status:          enum             // pending | running | completed | failed
  result_data_id:  UUID            // 추출 결과 데이터 (UDO) 참조
  quality_score:   float           // 추출 품질 점수 (0~1)
  manual_review:   boolean         // 수동 검토 필요 여부
  error_detail:    string          // 실패 시 상세 오류
  created_at:      timestamp
  completed_at:    timestamp
}
```

### 자동 vs 반자동 vs 수동 추출

| 모드 | 적용 조건 | 워크플로우 |
|------|----------|----------|
| **자동** | 품질 점수 > 0.9, 정형화된 포맷 | 수집 즉시 자동 추출 → 결과 저장 |
| **반자동** | 품질 점수 0.5~0.9 | 자동 추출 → 사용자 검토·수정 → 확정 |
| **수동** | 품질 점수 < 0.5, 비표준 포맷 | 사용자가 직접 추출 규칙 정의 → 실행 |

### 품질 점수 산출 기준

| 추출 유형 | 품질 지표 |
|----------|----------|
| PDF 테이블 | 테이블 구조 인식 신뢰도, 셀 값 파싱 성공률 |
| 3D 파라미터 | 요소 식별 성공률, 치수 추출 완전성 |
| 결함 감지 | 감지 신뢰도(confidence), IoU 점수 |
| 시계열 변환 | 결측치 비율, 파싱 성공률 |

## 3.03.4 추출 규칙 템플릿 관리

반복되는 추출 작업을 위한 **재사용 가능한 규칙 템플릿**:

```
ExtractionTemplate {
  id:              UUID
  name:            string         // "HullScan 두께 보고서 추출"
  extractor_type:  string
  config_template: JSONB          // 사전 정의된 추출 파라미터
  program_type:    string         // 연계 프로그램 (hullscan, frame3d, ...)
  created_by:      UUID
  usage_count:     integer        // 사용 횟수 (인기도)
}
```

- 프로그램별 자주 사용하는 추출 패턴을 템플릿으로 저장
- 신규 데이터 추출 시 템플릿 선택 → 파라미터 미세 조정 → 실행
- 조직/프로젝트별 공유 템플릿 관리

## 3.03.5 추출기 플러그인 아키텍처

신규 추출 유형 추가 시 코어 변경 없이 확장 가능한 플러그인 구조:

```typescript
interface DataExtractor {
  type: string;                           // 'pdf_table' | '3d_geometry' | ...
  displayName: string;
  supportedMimeTypes: string[];           // 처리 가능한 파일 유형

  // 추출 실행
  extract(source: File, config: ExtractConfig): Promise<ExtractionResult>;

  // 품질 평가
  evaluateQuality(result: ExtractionResult): QualityScore;

  // 설정 스키마 (UI 자동 생성용)
  getConfigSchema(): JSONSchema;

  // 미리보기 (전체 추출 전 샘플 확인)
  preview(source: File, config: ExtractConfig): Promise<PreviewResult>;
}
```

**현재 등록된 추출기**:
- `PdfTableExtractor` - PDF/문서 테이블 추출
- `GeometryParamExtractor` - 3D 모델 형상 파라미터
- `DefectDetectionExtractor` - 이미지 결함 감지·정량화
- `TimeSeriesExtractor` - 로그/센서 시계열 변환

**향후 확장 예시**:
- `SpectrumExtractor` - 진동/음향 스펙트럼 분석
- `ThermalExtractor` - 열화상 이미지 온도 분포
- `DocumentClassifier` - 문서 자동 분류·태깅

## 3.03.6 구현 기술 스택 요약

| 구성 요소 | 기술 | 역할 |
|----------|------|------|
| **텍스트/문서** | Apache Tika, Tesseract OCR | 텍스트·OCR 추출 |
| **테이블 감지** | Camelot, Tabula | PDF 테이블 구조 인식 |
| **3D 모델** | OpenCASCADE (OCCT) | STEP/IGES 파싱·분석 |
| **이미지 처리** | OpenCV, YOLOv8, Mask R-CNN | 결함 감지·분류 |
| **시계열 처리** | Pandas/Polars, TimescaleDB | 리샘플링·피처 생성 |
| **파이프라인 관리** | Celery / Bull Queue | 추출 작업 큐잉·실행 |
| **품질 평가** | 커스텀 스코어링 엔진 | 추출 품질 자동 산출 |
