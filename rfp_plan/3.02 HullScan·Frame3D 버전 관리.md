# 3.02 HullScan / Frame3D 프로그램 버전 관리 - 구현 방법론

## 3.02.1 개요

1차 적용 대상인 HullScan(선체 스캔/검사)과 Frame3D(3D 구조 해석) 프로그램의 입출력 데이터를 버전 단위로 추적·관리하는 체계를 구축한다. 버전 히스토리 자체도 데이터로 저장하며, 향후 다른 프로그램으로 확장 가능한 범용 프레임워크를 설계한다.

---

## 3.02.2 버전 관리 대상 정의

### HullScan 데이터 구조 (예상)

```
HullScan Project/
├── input/
│   ├── hull_geometry.stl          ← 선체 3D 모델
│   ├── scan_config.json           ← 스캔 설정 파라미터
│   └── reference_data/            ← 참조 데이터
├── output/
│   ├── scan_result.csv            ← 스캔 결과 (두께 측정 등)
│   ├── defect_map.png             ← 결함 맵 이미지
│   ├── report.pdf                 ← 결과 보고서
│   └── 3d_overlay.stl             ← 결과 오버레이 3D
└── logs/
    └── execution.log              ← 실행 로그
```

### Frame3D 데이터 구조 (예상)

```
Frame3D Project/
├── input/
│   ├── model.f3d                  ← 구조 모델 파일
│   ├── load_conditions.json       ← 하중 조건
│   ├── material_properties.json   ← 재료 물성
│   └── boundary_conditions.json   ← 경계 조건
├── output/
│   ├── stress_result.csv          ← 응력 해석 결과
│   ├── displacement.csv           ← 변위 결과
│   ├── visualization.vtk          ← 3D 시각화 데이터
│   └── summary_report.pdf         ← 요약 보고서
└── logs/
    └── solver.log                 ← 솔버 실행 로그
```

## 3.02.3 버전 관리 아키텍처

### 버전 스냅샷 모델

```
┌─────────────────────────────────────────────────────┐
│                   Program Registry                   │
│  프로그램 정의: HullScan, Frame3D, ... (확장 가능)     │
├─────────────────────────────────────────────────────┤
│                   Project (프로젝트)                   │
│  하나의 분석 대상 (예: "선박 A 선체 검사")              │
├─────────────────────────────────────────────────────┤
│                   Version (버전)                      │
│  v1 → v2 → v3 ...                                   │
│  각 버전 = input + output + config + log 스냅샷        │
├─────────────────────────────────────────────────────┤
│               Version History (버전 히스토리)           │
│  변경 사유, 변경자, 타임스탬프, diff 정보               │
│  ※ 히스토리 자체도 저장·조회 가능한 데이터              │
└─────────────────────────────────────────────────────┘
```

### 핵심 원칙
1. **불변성(Immutability)**: 저장된 버전의 파일은 변경 불가, 새 버전으로만 생성
2. **Content-Addressable**: 파일 해시 기반 저장으로 동일 파일 중복 방지
3. **Lazy Copy**: 변경되지 않은 파일은 이전 버전 참조 (저장 공간 절약)
4. **완전 재현성**: 특정 버전으로 돌아가면 동일한 입력/설정으로 재실행 가능

## 3.02.4 데이터 모델

### Version 테이블

```sql
CREATE TABLE program_versions (
  id              UUID PRIMARY KEY,
  project_id      UUID NOT NULL REFERENCES projects(id),
  program_type    VARCHAR(50) NOT NULL,    -- 'hullscan' | 'frame3d' | ...
  version_number  INTEGER NOT NULL,
  parent_version  UUID REFERENCES program_versions(id),  -- 이전 버전

  -- 스냅샷 참조
  input_snapshot   JSONB NOT NULL,   -- {파일명: storage_path, hash, size}
  output_snapshot  JSONB,            -- 실행 후 채워짐
  config_snapshot  JSONB NOT NULL,   -- 실행 파라미터 전체

  -- 메타
  status          VARCHAR(20),       -- draft | submitted | executed | archived
  created_by      UUID NOT NULL,
  created_at      TIMESTAMP DEFAULT NOW(),
  description     TEXT,              -- 버전 변경 사유
  tags            TEXT[],

  UNIQUE(project_id, version_number)
);
```

### Version History 테이블 (히스토리도 데이터)

```sql
CREATE TABLE version_history (
  id              UUID PRIMARY KEY,
  version_id      UUID NOT NULL REFERENCES program_versions(id),
  event_type      VARCHAR(30) NOT NULL,  -- 'created' | 'executed' | 'compared' | 'rolled_back'
  event_data      JSONB NOT NULL,        -- 이벤트별 상세 데이터
  actor_id        UUID NOT NULL,
  created_at      TIMESTAMP DEFAULT NOW(),

  -- 히스토리 자체를 검색·필터링 가능하게
  project_id      UUID NOT NULL,
  program_type    VARCHAR(50) NOT NULL
);

-- 히스토리에 대한 검색 색인
CREATE INDEX idx_vh_project ON version_history(project_id, created_at DESC);
CREATE INDEX idx_vh_program ON version_history(program_type, event_type);
```

## 3.02.5 핵심 기능 구현

### A. 버전 생성 워크플로우

```
1. 사용자가 프로젝트 선택 → "새 버전 생성" 클릭
2. 입력 파일 업로드 또는 이전 버전에서 복사
3. 실행 파라미터(config) 설정/수정
4. 변경 사유(description) 입력
5. 시스템:
   a) 각 파일 해시 계산 → 변경된 파일만 신규 저장
   b) 변경 안 된 파일 → 이전 버전 storage_path 참조 (Lazy Copy)
   c) version_number 자동 증가
   d) version_history에 'created' 이벤트 기록
6. 버전 상태: draft → (실행 시) executed
```

### B. 버전 비교 (Diff)

| 비교 대상 | 비교 방식 |
|----------|----------|
| 파일 목록 | 추가/삭제/변경된 파일 리스트 |
| 설정 파라미터 | JSON diff (변경된 키-값 하이라이트) |
| 수치 결과 (CSV) | 셀 단위 비교, 변화량/변화율 표시 |
| 3D 모델 | 형상 오버레이 비교 (3D Viewer 연동) |
| 보고서 | 텍스트 diff / 페이지 비교 |

### C. 버전 롤백

```
1. 사용자가 대상 버전 선택 → "이 버전으로 복원"
2. 시스템:
   a) 선택된 버전의 input + config 스냅샷을 새 버전으로 복사
   b) version_number 신규 채번 (덮어쓰기 아님)
   c) version_history에 'rolled_back' 이벤트 기록 (원본 버전 참조)
3. 결과: 이력 보존 + 새 버전으로 복원 (비파괴적)
```

### D. 버전 히스토리 조회

버전 히스토리 자체가 **검색 가능한 데이터**로 관리됨:
- 프로젝트별 전체 이력 타임라인
- 이벤트 유형별 필터 (생성/실행/비교/롤백)
- 사용자별 활동 이력
- 기간별 변경 추이 통계
- CSV/JSON 내보내기 지원

## 3.02.6 범용 프로그램 확장 프레임워크

### Program Adapter 인터페이스

신규 프로그램 추가 시 아래 인터페이스만 구현하면 버전 관리 체계에 통합:

```typescript
interface ProgramAdapter {
  // 프로그램 식별
  programType: string;                    // 'hullscan' | 'frame3d' | ...
  displayName: string;

  // 데이터 구조 정의
  getInputSchema(): FileSchema[];         // 입력 파일 유형/필수 여부
  getOutputSchema(): FileSchema[];        // 출력 파일 유형
  getConfigSchema(): JSONSchema;          // 파라미터 스키마

  // 메타데이터 추출
  extractMetadata(file: File): Metadata;  // 파일별 메타 추출

  // 비교 로직
  compareResults(v1: Version, v2: Version): DiffResult;

  // 검증
  validateInput(files: File[], config: Config): ValidationResult;
}
```

### 확장 예시

```
현재 등록:
  ├── HullScanAdapter   (선체 스캔/검사)
  └── Frame3DAdapter    (3D 구조 해석)

향후 확장:
  ├── FatigueAdapter    (피로 해석)
  ├── CFDAdapter        (유체 해석)
  ├── VibrationAdapter  (진동 해석)
  └── ...
```

각 Adapter는 **플러그인 형태**로 등록하며, 코어 버전 관리 로직의 수정 없이 프로그램을 추가할 수 있다.

## 3.02.7 저장 공간 최적화

| 전략 | 설명 | 절감 효과 |
|------|------|----------|
| **Content-Addressable** | 파일 해시 기반 저장, 동일 파일 1회만 저장 | 30~50% |
| **Lazy Copy** | 변경 안 된 파일은 이전 버전 참조 | 40~60% |
| **자동 계층 이동** | 오래된 버전 → Cool/Archive 자동 이동 | 저장 비용 절감 |
| **압축 저장** | 텍스트 기반 파일(CSV/JSON/로그) 압축 | 60~80% |
