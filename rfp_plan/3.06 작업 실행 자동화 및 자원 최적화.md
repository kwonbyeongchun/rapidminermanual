# 3.06 작업 실행 자동화 및 자원 최적화 - 구현 방법론

## 3.06.1 개요

등록된 데이터에 대한 순차/병렬 작업 실행, 배치 스케줄링, 작업 큐 관리, 라이선스·하드웨어 자원의 실시간 모니터링 및 우선순위 기반 자원 배분을 구현한다.

---

## 3.06.2 작업 실행 아키텍처

```
┌───────────────────────────────────────────────────────────┐
│                    사용자 요청 (웹 UI / API)                 │
│  [단건 실행]  [배치 실행]  [스케줄 등록]  [재실행]             │
└──────────────────────┬────────────────────────────────────┘
                       ▼
┌───────────────────────────────────────────────────────────┐
│                 Job Scheduler (스케줄러)                    │
│  ┌──────────┐  ┌──────────┐  ┌──────────────┐            │
│  │ 즉시 실행  │  │ Cron     │  │ 이벤트 트리거  │            │
│  │ (Instant) │  │ Schedule │  │ (파일 등록 시) │            │
│  └──────────┘  └──────────┘  └──────────────┘            │
└──────────────────────┬────────────────────────────────────┘
                       ▼
┌───────────────────────────────────────────────────────────┐
│              Job Queue (작업 대기열)                        │
│  ┌───────┐  ┌───────┐  ┌───────┐  ┌───────┐             │
│  │ Job 1 │→ │ Job 2 │→ │ Job 3 │→ │ ...   │             │
│  │ P:High│  │ P:Med │  │ P:Low │  │       │             │
│  └───────┘  └───────┘  └───────┘  └───────┘             │
│                                                          │
│  정책: 우선순위 큐 + FIFO (동일 우선순위 내)                 │
└──────────────────────┬────────────────────────────────────┘
                       ▼
┌───────────────────────────────────────────────────────────┐
│            Resource Manager (자원 관리자)                   │
│  ┌──────────────┐  ┌──────────────┐                      │

│  └──────────────┘  └──────────────┘                      │

                       ▼
┌───────────────────────────────────────────────────────────┐
│              Worker Pool (실행 워커)                       │
│  ┌─────────┐  ┌─────────┐  ┌─────────┐                  │
│  │ Worker1 │  │ Worker2 │  │ Worker3 │  ...              │
│  │ HullScan│  │ Frame3D │  │ ML Job  │                  │
│  └─────────┘  └─────────┘  └─────────┘                  │
└───────────────────────────────────────────────────────────┘
```

## 3.06.3 작업(Job) 데이터 모델

```sql
CREATE TABLE jobs (
  id              UUID PRIMARY KEY,
  job_type        VARCHAR(50) NOT NULL,    -- 'hullscan' | 'frame3d' | 'extraction' | 'ml_training'
  priority        INTEGER DEFAULT 5,       -- 1(최고) ~ 10(최저)
  status          VARCHAR(20) NOT NULL,    -- 'queued' | 'waiting_resource' | 'running'
                                           -- | 'completed' | 'failed' | 'cancelled'

  -- 입력
  input_data      JSONB NOT NULL,          -- 입력 파일/파라미터 참조
  config          JSONB,                   -- 실행 설정

  -- 실행 정보
  worker_id       VARCHAR(100),            -- 실행 워커 ID
  started_at      TIMESTAMP,
  completed_at    TIMESTAMP,
  progress        INTEGER DEFAULT 0,       -- 0~100%

  -- 결과
  output_data     JSONB,                   -- 출력 파일 참조
  error_message   TEXT,
  exit_code       INTEGER,

  -- 재시도
  retry_count     INTEGER DEFAULT 0,
  max_retries     INTEGER DEFAULT 3,

  -- 관계
  batch_id        UUID,                    -- 배치 작업 그룹
  project_id      UUID NOT NULL,
  created_by      UUID NOT NULL,
  created_at      TIMESTAMP DEFAULT NOW()
);
```

## 3.06.4 실행 모드

### A. 단건 실행
- 사용자가 데이터 1건 선택 → 프로그램·파라미터 지정 → 즉시 실행
- 실행 상태 실시간 표시 (WebSocket)

### B. 배치 실행 (대량)
```
1. 사용자가 다수 데이터 선택 (체크박스 / 필터 조건)
2. 실행 모드 선택:
   ├─ 순차 (Sequential): 1건 완료 후 다음 실행
   └─ 병렬 (Parallel): 최대 N건 동시 실행 (자원 한도 내)
3. 배치 Job 생성 → 하위 Job들 자동 큐잉
4. 배치 전체 진행률 + 개별 Job 상태 표시
5. 부분 실패 처리:
   ├─ 실패 Job만 재시도 가능
   ├─ 성공 Job 결과는 보존
   └─ 배치 상태: partial_success
```

### C. 스케줄 실행
| 스케줄 유형 | 설정 예시 | 구현 |
|-----------|----------|------|
| **주기 반복** | 매일 02:00, 매주 월요일 | Cron 표현식 |
| **이벤트 기반** | 새 파일 등록 시 자동 실행 | Event Listener + Queue |
| **조건부** | 데이터 N건 축적 시 실행 | Threshold Trigger |

## 3.06.5 자원·라이선스 관리

### 라이선스 풀 관리

```
┌────────────────────────────────────────┐
│           License Pool                  │
│                                        │
│  HullScan:  ████████░░  8/10 사용 중    │
│  Frame3D:   ██████░░░░  6/10 사용 중    │
│  ML Engine: ████░░░░░░  4/10 사용 중    │
│                                        │
│  ■ 사용 중   ░ 가용                     │
└────────────────────────────────────────┘
```

### 자원 현황 모니터링 대시보드

```
┌────────────────────────────────────────────────┐
│              자원 현황 대시보드                    │
├────────────────────┬───────────────────────────┤
│  라이선스 현황       │  하드웨어 현황              │
│  HullScan: 2 남음   │  CPU:  ███████░░░ 72%    │
│  Frame3D:  4 남음   │  RAM:  ████████░░ 81%    │
│  ML:       6 남음   │  Disk: █████░░░░░ 48%    │
├────────────────────┼───────────────────────────┤
│  대기 중 작업: 5건   │  실행 중 작업: 12건         │
│  예상 대기: ~15분    │  평균 소요: ~8분            │
└────────────────────┴───────────────────────────┘
```

### 실행 제어 로직

```
작업 실행 요청 수신
  │
  ├─ 라이선스 확인 ─→ 부족 → 대기열 (사용자 알림: "라이선스 대기 중, 예상 N분")
  │
  ├─ 하드웨어 확인 ─→ 부족 → 대기열 (사용자 알림: "자원 대기 중")
  │
  └─ 모두 충분 ─→ 라이선스 점유 + 워커 할당 + 실행 시작
                     │
                     └─ 완료/실패 시 → 라이선스 반환 + 다음 대기 작업 실행
```

## 3.06.6 우선순위·대기열 정책

### 우선순위 결정 요소

| 요소 | 가중치 | 설명 |
|------|--------|------|
| 사용자 지정 긴급도 | 40% | 긴급 / 보통 / 낮음 |
| 조직 등급 | 25% | 프리미엄 고객 > 일반 고객 |
| 대기 시간 | 20% | 오래 대기할수록 우선순위 상향 (Aging) |
| 작업 크기 | 15% | 소규모 작업 우선 (Short Job First 옵션) |

### 대기열 정책 (발주처 협의 항목)
- **기본 정책**: 우선순위 큐 + 동일 우선순위 내 FIFO
- **공정성 보장**: 조직별 동시 실행 상한 (예: 최대 전체의 30%)
- **기아 방지**: Aging 메커니즘 (대기 10분마다 우선순위 1단계 상향)
- **예약 자원**: 긴급 작업용 자원 10% 항시 예약

## 3.06.7 실패 처리·재시도 정책

| 실패 유형 | 재시도 | 처리 방식 |
|----------|--------|----------|
| 일시적 오류 (네트워크, 타임아웃) | 자동 3회 | 지수 백오프 (30s → 60s → 120s) |
| 라이선스 만료 | 대기 후 재시도 | 라이선스 반환 대기 → 자동 재실행 |
| 입력 데이터 오류 | 재시도 안 함 | 사용자 알림 + 오류 상세 표시 |
| 프로그램 크래시 | 자동 1회 | 재시도 후 실패 시 관리자 알림 |
| 디스크 부족 | 재시도 안 함 | 관리자 긴급 알림 |

## 3.06.8 구현 기술 스택

| 구성 요소 | 기술 | 역할 |
|----------|------|------|
| **Job Queue** | RabbitMQ 또는 Redis (Bull) | 작업 큐잉, 우선순위, 재시도 |
| **Scheduler** | node-cron / APScheduler | 주기/이벤트 스케줄링 |
| **Worker** | 컨테이너 기반 워커 프로세스 | 격리된 실행 환경 |
| **모니터링** | Prometheus + Grafana | 자원 사용량, 작업 통계 |
| **실시간 통신** | WebSocket (Socket.IO) | 작업 상태 실시간 전달 |
